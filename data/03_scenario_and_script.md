# 03. 시나리오와 스크립트

## 적용 화면 또는 기능

본 문서는 Performance Station에서 성능테스트를 수행하기 위해 시나리오를 등록하고 JMeter 스크립트를 업로드·검증·연결하는 방법을 설명합니다.

주요 적용 화면 및 기능은 다음과 같습니다.

* 시나리오 목록 화면
* 시나리오 등록 화면
* 시나리오 상세 화면
* 스크립트 관리 화면
* JMeter 스크립트 업로드 화면
* 스크립트 검증 화면
* 테스트 데이터 관리 화면
* 시나리오-스크립트 연결 기능

Performance Station에서 일반적인 시나리오 구성 흐름은 다음과 같습니다.

테스트 생성
→ 시나리오 등록
→ JMeter 스크립트 준비
→ 스크립트 업로드
→ 스크립트 검증
→ 테스트 데이터 등록
→ 시나리오와 스크립트 연결
→ 부하 조건 설정
→ 테스트 실행

---

## 시나리오란?

시나리오는 실제 사용자가 시스템에서 수행하는 하나의 업무 흐름 또는 기능 단위를 의미합니다.

예를 들어 보험 시스템의 사용자가 다음과 같은 업무를 수행한다고 가정합니다.

로그인
→ 고객 조회
→ 계약 조회
→ 해약환급금 조회
→ 로그아웃

이 전체 업무 흐름을 하나의 시나리오로 구성할 수도 있고, 필요에 따라 업무별로 여러 개의 시나리오로 분리할 수도 있습니다.

예:

* 로그인
* 고객조회
* 계약조회
* 보험료 계산
* 해약환급금 조회

성능테스트에서는 실제 운영 환경에서 발생하는 업무 비율을 반영하여 여러 시나리오를 동시에 실행하는 경우가 많습니다.

예:

* 고객조회: 40%
* 계약조회: 30%
* 보험료 계산: 20%
* 해약환급금 조회: 10%

---

# 사전 조건

## 1. JMeter 스크립트 준비

Performance Station에서 사용할 성능테스트 스크립트를 사전에 준비합니다.

일반적으로 Apache JMeter 기반의 다음 파일을 사용할 수 있습니다.

* `.jmx` 파일
* CSV 테스트 데이터 파일
* Properties 파일
* 기타 스크립트에서 참조하는 데이터 파일

대표적인 스크립트 파일 예:

`customer_search.jmx`

`login.jmx`

`contract_search.jmx`

실제 지원되는 파일 형식과 JMeter 버전은 Performance Station 운영 환경에 따라 다를 수 있으므로 시스템 설정을 확인합니다.

---

## 2. JMeter 버전 확인

JMeter 스크립트를 생성한 버전과 Performance Station에서 지원하는 JMeter 버전이 다르면 정상적으로 실행되지 않을 수 있습니다.

스크립트 작성 전에 다음을 확인합니다.

* Performance Station 지원 JMeter 버전
* 사용 가능한 Plugin
* Java 버전
* 외부 Library 사용 가능 여부
* 사용자 정의 Plugin 사용 가능 여부

특히 로컬 PC에서는 정상적으로 실행되지만 Performance Station에서는 실행되지 않는 경우 JMeter 버전이나 Plugin 차이가 원인일 수 있습니다.

---

## 3. 테스트 계정 준비

로그인이 필요한 업무의 경우 성능테스트용 계정을 준비합니다.

예:

* 사용자 ID
* 비밀번호
* 고객번호
* 계약번호
* 사용자 권한

성능테스트에서는 하나의 계정을 여러 Virtual User가 동시에 사용하면 세션 충돌이 발생할 수 있습니다.

따라서 가능하면 Virtual User별로 사용할 수 있는 충분한 테스트 계정을 확보합니다.

예:

`user001`

`user002`

`user003`

...

`user300`

---

## 4. 테스트 데이터 준비

테스트에서 사용할 업무 데이터를 준비합니다.

예:

* 고객번호
* 계약번호
* 상품번호
* 계좌번호
* 사용자 ID
* 검색어
* 요청 파라미터

대량의 테스트 데이터를 사용하는 경우 CSV 파일로 관리하는 것을 권장합니다.

예:

`test_data.csv`

```text
user_id,password,customer_no
user001,password01,C100001
user002,password02,C100002
user003,password03,C100003
```

---

## 5. 대상 시스템 접근 확인

스크립트 업로드 전에 Performance Station 또는 Load Generator에서 대상 시스템에 접근할 수 있는지 확인합니다.

확인 항목:

* 대상 URL 접근 가능 여부
* DNS 연결
* 방화벽
* Port
* VPN 또는 사내망
* SSL 인증서
* Proxy 설정

예:

`https://test.example.com`

스크립트가 정상이어도 Load Generator에서 대상 서버에 접근할 수 없다면 테스트 실행이 실패할 수 있습니다.

# 단계별 절차

# 1. 시나리오 등록

## STEP 1. 테스트 선택

Performance Station에서 시나리오를 등록할 프로젝트와 테스트를 선택합니다.

일반적인 구조는 다음과 같습니다.

프로젝트
→ 테스트
→ 시나리오

테스트 상세 화면에서 시나리오, 시나리오 관리 또는 유사한 메뉴로 이동합니다.

---

## STEP 2. 신규 시나리오 생성

시나리오 목록 화면에서 다음과 같은 버튼을 선택합니다.

* 시나리오 등록
* 신규 시나리오
* * 시나리오

시나리오 생성 화면에서 기본 정보를 입력합니다.

---

## STEP 3. 시나리오 정보 입력

시나리오에는 다음 정보를 입력합니다.

### 시나리오명

실제 수행하는 업무를 쉽게 구분할 수 있도록 작성합니다.

예:

* 로그인
* 고객조회
* 계약조회
* 보험료계산
* 해약환급금조회
* 계약상세조회

---

### 시나리오 설명

시나리오에서 수행하는 업무 흐름을 작성합니다.

예:

로그인 → 고객검색 → 고객 상세조회 → 계약조회 → 로그아웃

또는

고객번호를 이용하여 고객정보와 보유 계약을 조회하는 업무

---

### 업무 구분

필요한 경우 다음과 같이 업무 영역을 구분할 수 있습니다.

* Portal
* 콜센터
* 모바일
* 영업지원
* 관리자
* 배치

---

### 중요도

서비스에 따라 주요 시나리오와 보조 시나리오를 구분할 수 있습니다.

예:

* 핵심
* 중요
* 일반

실제 운영에서 사용 빈도가 높은 업무는 성능테스트에서 반드시 포함하는 것이 좋습니다.

---

## STEP 4. 시나리오 저장

입력한 정보를 확인한 후 저장 또는 등록 버튼을 선택합니다.

등록이 완료되면 시나리오 목록에 신규 시나리오가 표시됩니다.

---

# 2. JMeter 스크립트 업로드

## STEP 1. JMeter 스크립트 준비

로컬 환경에서 JMeter 스크립트가 정상적으로 실행되는지 먼저 확인합니다.

최소한 다음 항목을 확인합니다.

* 요청 URL
* HTTP Method
* Request Parameter
* Header
* Cookie
* 인증 정보
* 응답 코드
* Assertion
* Correlation

로컬 JMeter에서 1명의 사용자 기준으로 정상적인 업무 수행이 가능한 상태에서 업로드하는 것을 권장합니다.

---

## STEP 2. 스크립트 관리 화면 이동

Performance Station에서 스크립트 관리, 스크립트 업로드, JMeter Script 등의 메뉴로 이동합니다.

신규 스크립트 등록을 선택합니다.

---

## STEP 3. JMX 파일 업로드

등록할 `.jmx` 파일을 선택합니다.

예:

`customer_search_v1.0.jmx`

파일을 선택한 후 다음 정보를 입력할 수 있습니다.

* 스크립트명
* 버전
* 설명
* 작성자
* 대상 시스템
* 등록일

---

## STEP 4. 관련 파일 등록

JMeter 스크립트에서 외부 파일을 사용하는 경우 필요한 파일을 함께 등록합니다.

예:

* CSV
* Properties
* 인증서
* 사용자 정의 설정 파일

예:

`users.csv`

`customer_data.csv`

`test.properties`

JMeter 스크립트에서 파일 경로를 직접 지정한 경우 Performance Station 실행 환경에서 동일한 경로를 사용할 수 있는지 확인합니다.

---

# 3. 업로드한 스크립트 검증

스크립트를 업로드한 후에는 실제 부하를 발생시키기 전에 스크립트 검증을 수행합니다.

이 단계는 매우 중요합니다.

스크립트에 오류가 있는 상태에서 수백 명의 Virtual User를 실행하면大量의 오류 요청이 발생할 수 있습니다.

---

## 검증 항목 1. JMX 문법

JMeter에서 정상적으로 읽을 수 있는 JMX 파일인지 확인합니다.

다음과 같은 문제가 있는 경우 검증이 실패할 수 있습니다.

* JMX 파일 손상
* JMeter 버전 차이
* XML 문법 오류
* 지원하지 않는 Plugin 사용

---

## 검증 항목 2. URL

스크립트에서 호출하는 대상 URL을 확인합니다.

예:

개발계 URL

`https://dev.example.com`

검증계 URL

`https://stg.example.com`

운영계 URL

`https://www.example.com`

로컬에서 사용하던 URL이 그대로 남아 있지 않은지 반드시 확인합니다.

---

## 검증 항목 3. Parameter

요청에 필요한 파라미터가 정상적으로 전달되는지 확인합니다.

예:

* customerId
* contractNo
* productCode
* userId

JMeter Variable이 잘못 지정되어 있으면 빈 값이 전달될 수 있습니다.

예:

`${customerId}`

변수명이 CSV 파일의 컬럼명과 정확히 일치하는지 확인합니다.

---

## 검증 항목 4. 인증

로그인이 필요한 시스템에서는 인증 처리가 정상적으로 동작하는지 확인합니다.

대표적인 인증 방식:

* Session
* Cookie
* JWT
* OAuth
* SSO
* 인증 Token

로그인 이후 생성되는 세션이나 토큰을 다음 요청에서 정상적으로 전달해야 합니다.

---

## 검증 항목 5. Correlation

동적으로 생성되는 값을 다음 요청에서 사용해야 하는 경우 Correlation 처리가 필요합니다.

예:

로그인 요청

↓

Session ID 생성

↓

Session ID 추출

↓

다음 요청에서 Session ID 사용

JMeter에서는 다음 기능을 사용할 수 있습니다.

* JSON Extractor
* Regular Expression Extractor
* CSS Selector
* XPath Extractor

---

## 검증 항목 6. Assertion

응답이 정상인지 확인하기 위해 Assertion을 사용하는 것이 좋습니다.

예:

HTTP 응답이 200이라고 해도 실제 응답 본문이 다음과 같을 수 있습니다.

```text
사용자 인증 실패
```

따라서 단순히 HTTP Code만 확인하지 않고 응답 내용도 함께 확인하는 것이 좋습니다.

예:

* Response Code Assertion
* Response Text Assertion
* JSON Assertion

---

## 검증 항목 7. Think Time

실제 사용자가 화면을 보고 다음 행동을 하기까지 걸리는 시간을 Think Time으로 설정할 수 있습니다.

예:

고객조회

↓

30초 확인

↓

계약조회

JMeter에서는 Timer를 이용하여 Think Time을 구현할 수 있습니다.

단, Performance Station에서 별도로 Think Time을 관리하는 경우 JMeter 내부 Timer와 중복 적용되지 않도록 확인합니다.

---

## 검증 항목 8. 로컬 경로

스크립트에서 로컬 PC의 절대 경로를 사용하지 않는 것이 좋습니다.

잘못된 예:

`C:\Users\user\Desktop\test_data.csv`

Performance Station의 Load Generator에는 해당 경로가 존재하지 않습니다.

가능하면 상대경로 또는 Performance Station에서 제공하는 데이터 관리 기능을 사용합니다.

---

# 4. 시나리오와 스크립트 연결

예:

시나리오

고객조회

↓

JMeter 스크립트

`customer_search_v1.0.jmx`

---

1. 프로젝트를 선택합니다.

3. 시나리오 목록으로 이동합니다.
4. 연결할 시나리오를 선택합니다.
5. 스크립트 연결 또는 스크립트 선택을 선택합니다.
6. 등록된 JMeter 스크립트를 선택합니다.
7. 저장합니다.

# 시나리오 구성 권장 방법

성능테스트 시나리오는 실제 운영 업무를 기준으로 작성하는 것이 중요합니다.

운영에서 거의 사용하지 않는 기능을 높은 비율로 테스트하거나, 실제 사용량이 많은 업무를 제외하면 현실적인 테스트 결과를 얻기 어렵습니다.

---

## 운영 사용량 기반 시나리오 구성

예를 들어 실제 운영의 업무 비율이 다음과 같다고 가정합니다.

* 고객조회: 40%
* 계약조회: 30%
* 보험료계산: 20%
* 해약환급금조회: 10%

성능테스트에서도 가능한 한 유사한 비율로 부하를 구성합니다.

---

# 시나리오 작성 권장 구조

시나리오 문서는 다음 정보를 포함하는 것이 좋습니다.

### 시나리오명

고객 계약조회

### 업무 목적

고객의 기본정보와 보유 계약을 조회합니다.

### 업무 흐름

로그인

↓

고객검색

↓

고객 선택

↓

계약 목록 조회

↓

계약 상세조회

↓

로그아웃

### 사용 데이터

* 사용자 ID

# 스크립트 버전 관리

JMeter 스크립트는 테스트 과정에서 반복적으로 수정됩니다.

따라서 반드시 버전을 관리하는 것이 좋습니다.

좋은 예:

`customer_search_v1.0.jmx`

`customer_search_v1.1.jmx`

`customer_search_v1.2.jmx`

---

## 버전 변경 예

### v1.0

최초 스크립트 작성

### v1.1

Correlation 수정

### v1.2

테스트 데이터 CSV 적용

### v1.3

Think Time 수정

---

## 테스트 수행 이후 스크립트 변경

이미 테스트를 수행한 스크립트를 수정하면 나중에 동일한 테스트를 재현하기 어려울 수 있습니다.

따라서 실행에 사용한 스크립트는 가급적 수정하지 않고 새로운 버전으로 등록하는 것을 권장합니다.

예:

기존

`customer_search_v1.2.jmx`

수정 후

`customer_search_v1.3.jmx`

# 주의사항

## 1. 로컬 JMeter에서 먼저 검증합니다.

Performance Station에 업로드하기 전에 로컬 JMeter에서 최소 1명의 Virtual User로 정상 실행되는지 확인합니다.

확인 항목:

* 요청 성공
* 응답 데이터 정상
* 로그인 정상
* Session 유지
* Parameter 정상
* Correlation 정상
* Assertion 정상

---

## 2. Thread Group 설정을 확인합니다.

JMeter Script 내부의 Thread Group과 Performance Station의 Virtual User 설정이 중복될 수 있습니다.

예를 들어 JMeter에 다음과 같이 설정되어 있다고 가정합니다.

Thread: 100

Performance Station에서도

Virtual User: 100

으로 설정하면 실제 실행 방식에 따라 의도하지 않은 부하가 발생할 수 있습니다.

Performance Station이 Thread를 직접 제어하는 구조라면 JMeter 스크립트는 일반적으로 최소 단위로 작성하는 것이 좋습니다.

---

## 3. 테스트 계정을 중복 사용하지 않습니다.

하나의 계정을 여러 Virtual User가 동시에 사용하는 경우 다음 문제가 발생할 수 있습니다.

* Session 충돌
* 중복 로그인
* 강제 로그아웃
* 데이터 Lock
* 비정상 응답

가능하면 Virtual User별로 별도의 테스트 계정을 사용합니다.

---

## 4. 테스트 데이터가 충분한지 확인합니다.

Virtual User보다 테스트 데이터가 적으면 동일한 데이터가 반복 사용될 수 있습니다.

예:

Virtual User: 300명

테스트 계정: 10개

이 경우 여러 Virtual User가 동일 계정을 동시에 사용할 가능성이 높습니다.

충분한 테스트 데이터를 확보하는 것이 좋습니다.

---

## 5. Hard Coding을 최소화합니다.

스크립트 내부에 다음 정보를 직접 입력하지 않는 것이 좋습니다.

* URL
* 사용자 ID
* Password
* 고객번호
* 계약번호

가능하면 변수나 외부 데이터 파일로 관리합니다.

예:

`${BASE_URL}`

`${USER_ID}`

`${CUSTOMER_NO}`

---

## 6. 운영 비밀번호를 스크립트에 저장하지 않습니다.

실제 운영 사용자 ID, Password, Token 또는 개인정보를 JMX 파일 안에 직접 저장하지 않도록 주의합니다.

성능테스트용 계정과 별도의 테스트 데이터를 사용합니다.

---

# 스크립트 검증 실패 시 자주 발생하는 원인

## JMeter에서 파일을 읽을 수 없습니다.

### 원인

* JMX 파일 손상
* JMeter 버전 불일치
* XML 오류

### 조치

로컬 JMeter에서 파일이 정상적으로 열리는지 확인합니다.

---

## Plugin을 찾을 수 없습니다.

### 원인

스크립트에서 Performance Station에 설치되지 않은 JMeter Plugin을 사용한 경우입니다.

### 조치

Performance Station에서 지원하는 Plugin인지 확인하거나 기본 JMeter 기능으로 변경합니다.

---

## CSV 파일을 찾을 수 없습니다.

### 원인

로컬 PC의 절대 경로를 사용하고 있을 가능성이 있습니다.

예:

`C:\test\data.csv`

### 조치

Performance Station에 CSV를 함께 등록하고 상대경로 또는 제공되는 데이터 경로를 사용합니다.

---

## 로그인은 성공하지만 다음 요청이 실패합니다.

### 원인

* Session 미전달
* Cookie 미전달
* Token 추출 실패
* Correlation 오류

### 조치

로그인 응답에서 Session 또는 Token이 정상적으로 추출되는지 확인합니다.

---

## HTTP 200인데 테스트가 실패합니다.

### 원인

서버가 HTTP 200을 반환하지만 응답 내용은 업무 오류일 수 있습니다.

예:

```text
고객 정보가 존재하지 않습니다.
```

### 조치

Response Assertion을 이용하여 실제 업무 성공 여부를 확인합니다.

---

## 응답시간이 비정상적으로 길게 나옵니다.

### 가능한 원인

* 네트워크 지연
* 대상 시스템 문제
* JMeter Timer
* Connection Timeout
* Read Timeout
* 외부 시스템 지연
* 테스트 데이터 오류

JMeter 스크립트 문제인지 대상 시스템 문제인지 구분하여 분석합니다.

---

# 테스트 실행 전 최종 체크리스트

시나리오와 스크립트 설정이 완료되면 실제 부하를 적용하기 전에 다음을 확인합니다.

### 시나리오

* 실제 업무 흐름과 동일한가?
* 주요 업무가 빠지지 않았는가?
* 업무 비율이 운영과 유사한가?

### 스크립트

* 로컬 JMeter에서 정상 실행되는가?
* JMeter 버전이 호환되는가?
* 미지원 Plugin이 없는가?
* URL이 올바른가?
* 인증이 정상인가?
* Correlation이 정상인가?
* Assertion이 설정되어 있는가?

### 테스트 데이터

* 테스트 계정이 충분한가?
* 고객번호 등 업무 데이터가 충분한가?
* 중복 데이터 문제가 없는가?

### 실행 환경

* Load Generator에서 대상 서버 접근이 가능한가?
* 방화벽이 열려 있는가?
* 대상 환경이 올바른가?

# 시나리오 및 스크립트 권장 흐름

Performance Station에서 스크립트를 준비할 때 다음 순서로 진행하는 것을 권장합니다.

① 실제 사용자 업무 정의
→ ② 핵심 시나리오 선정
→ ③ JMeter 스크립트 작성
→ ④ 로컬 JMeter 단건 테스트
→ ⑤ Parameter 및 Correlation 적용
→ ⑥ 테스트 데이터 준비
→ ⑦ Performance Station 업로드
→ ⑧ 스크립트 검증
→ ⑨ 시나리오-스크립트 연결
→ ⑩ 소규모 부하 테스트
→ ⑪ 본 성능테스트 수행

특히 처음부터 큰 부하를 적용하지 않고 1 VUser → 소규모 부하 → 목표 부하 순서로 단계적으로 검증하는 것이 안전합니다.

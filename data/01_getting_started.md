# 01. 시작하기

## 적용 화면 또는 기능

본 문서는 Performance Station을 처음 사용하는 사용자가 시스템에 접속하고, 성능테스트를 수행하기 위한 기본 흐름을 이해할 수 있도록 다음 화면 및 기능을 대상으로 합니다.

* Performance Station 로그인 화면
* 메인 대시보드
* 프로젝트 목록 및 프로젝트 관리 화면
* 사용자 및 권한 관리 기능
* 테스트(Test) 생성 및 관리 화면
* 시나리오 등록 화면
* 부하(Load) 설정 화면
* 테스트 실행 및 모니터링 화면
* 테스트 결과 및 리포트 조회 화면

Performance Station의 기본적인 사용 흐름은 다음과 같습니다.

로그인 → 프로젝트 선택/생성 → 테스트 생성 → 시나리오 등록 → 부하 설정 → 테스트 실행 → 실시간 모니터링 → 결과 확인 및 분석

---

## 사전 조건

Performance Station을 사용하기 전에 다음 사항을 확인합니다.

### 1. 사용자 계정

Performance Station에 등록된 사용자 계정이 필요합니다.

사용자 계정은 시스템 운영자 또는 관리자에 의해 사전에 생성되거나, 조직에서 정의한 계정 발급 절차를 통해 등록되어야 합니다.

회사 내부 시스템과 연동되어 있는 환경에서는 사내 계정 또는 SSO(Single Sign-On) 계정을 사용할 수 있습니다.

### 2. 사용자 권한

사용자는 부여된 권한에 따라 사용할 수 있는 기능이 달라질 수 있습니다.

일반적으로 다음과 같은 권한 체계를 사용할 수 있습니다.

* 관리자(Admin)

  * 사용자 및 권한 관리
  * 전체 프로젝트 조회 및 관리
  * 시스템 설정 관리
  * 프로젝트 생성/수정/삭제

* 프로젝트 관리자 또는 테스트 담당자

  * 담당 프로젝트 관리
  * 테스트 생성
  * 시나리오 등록
  * 부하 설정
  * 테스트 실행
  * 결과 조회

* 일반 사용자 또는 조회 사용자

  * 할당된 프로젝트 조회
  * 테스트 진행 상태 확인
  * 테스트 결과 및 리포트 조회
  * 일부 설정 기능 제한

※ 실제 권한 명칭과 범위는 Performance Station 운영 정책에 따라 다를 수 있습니다.

### 3. 프로젝트 접근 권한

계정이 존재하더라도 프로젝트에 사용자 권한이 할당되어 있지 않으면 해당 프로젝트가 목록에 표시되지 않거나 테스트를 생성할 수 없습니다.

프로젝트가 보이지 않는 경우 다음 항목을 확인합니다.

1. 사용자 계정이 정상 등록되어 있는지
2. 해당 프로젝트에 사용자 또는 조직이 등록되어 있는지
3. 프로젝트 생성/테스트 실행 권한이 부여되어 있는지

### 4. 접속 환경

Performance Station 접속을 위해 다음 환경을 확인합니다.

* 사내망 또는 접속 가능한 네트워크 환경
* Performance Station 접속 URL
* 권장 웹 브라우저
* 필요한 경우 VPN 또는 사내 보안망 접속
* 팝업 및 다운로드 차단 여부

성능테스트 실행 환경에 따라 부하발생기(Load Generator), Agent 또는 테스트 대상 시스템과의 네트워크 연결이 추가로 필요할 수 있습니다.

---

## 단계별 절차

### 1. Performance Station 로그인

1. 웹 브라우저에서 Performance Station 접속 URL에 접속합니다.
2. 사용자 ID와 비밀번호를 입력합니다.
3. 환경에 따라 사내 계정 또는 SSO 인증을 수행합니다.
4. 인증이 정상적으로 완료되면 Performance Station 메인 화면으로 이동합니다.

로그인 이후에는 사용자에게 부여된 권한을 기준으로 사용할 수 있는 프로젝트와 메뉴가 표시됩니다.

### 로그인 실패 시 확인 사항

로그인이 되지 않을 경우 다음 사항을 확인합니다.

* 사용자 ID 또는 비밀번호 오류
* 계정 미등록 또는 계정 잠금
* 사용자 권한 미부여
* VPN 또는 사내망 미접속
* Performance Station 서버 또는 인증 서버 장애
* 접속 URL 오류

지속적으로 로그인에 실패하는 경우 시스템 관리자에게 계정 상태와 권한 정보를 확인합니다.

---

### 2. 메인 화면 구성

로그인하면 Performance Station 메인 대시보드 또는 프로젝트 목록 화면이 표시됩니다.

메인 화면에서는 일반적으로 다음 정보를 확인할 수 있습니다.

#### 프로젝트

사용자가 접근 가능한 성능테스트 프로젝트 목록을 확인할 수 있습니다.

프로젝트는 특정 시스템이나 서비스에 대해 수행하는 여러 성능테스트를 관리하기 위한 최상위 관리 단위입니다.

예:

* 영업지원시스템 성능검증
* 통합인증 성능검증
* 모바일 서비스 성능테스트

#### 테스트(Test)

프로젝트 안에서 실제로 수행하는 개별 성능테스트를 의미합니다.

하나의 프로젝트에는 여러 테스트를 생성할 수 있습니다.

예:

* 기준 성능테스트
* 최대 부하 테스트
* 안정성 테스트
* 가용성 테스트
* 장애 전환 테스트

#### 최근 테스트

최근 생성하거나 실행한 테스트의 상태를 확인할 수 있습니다.

예:

* 준비
* 실행 대기
* 실행 중
* 완료
* 실패

#### 실행 현황

현재 수행 중인 성능테스트의 진행 상태를 확인할 수 있습니다.

테스트 실행 중에는 다음과 같은 주요 성능지표를 확인할 수 있습니다.

* TPS 또는 처리량
* 응답시간
* Virtual User
* 오류율
* CPU 사용률
* Memory 사용률
* 시스템 또는 애플리케이션 모니터링 지표

#### 결과 및 리포트

완료된 테스트의 결과를 조회하고 분석할 수 있습니다.

테스트별 처리량, 응답시간, 오류율 등의 결과를 이용하여 목표 성능 충족 여부를 판단합니다.

---

### 3. 프로젝트 목록 확인

메인 화면에서 프로젝트 메뉴를 선택하면 사용자가 접근할 수 있는 프로젝트 목록을 확인할 수 있습니다.

프로젝트 목록에서는 일반적으로 다음 정보를 확인합니다.

* 프로젝트명
* 대상 시스템
* 프로젝트 담당자
* 프로젝트 기간
* 테스트 개수
* 최근 테스트 실행 일시
* 프로젝트 상태

기존 프로젝트에서 테스트를 수행하는 경우 해당 프로젝트를 선택합니다.

새로운 시스템에 대해 성능테스트를 수행하는 경우 권한이 있는 사용자는 신규 프로젝트를 생성합니다.

---

## Performance Station 전체 사용 흐름

Performance Station을 이용한 일반적인 성능테스트 수행 절차는 다음과 같습니다.

### STEP 1. 프로젝트 생성

성능테스트를 수행할 대상 시스템에 대한 프로젝트를 생성합니다.

프로젝트에는 다음과 같은 정보를 등록할 수 있습니다.

* 프로젝트명
* 대상 시스템
* 프로젝트 설명
* 담당자
* 테스트 기간
* 참여 사용자

예:

프로젝트명: 영업지원시스템 성능검증

하나의 프로젝트 안에서 기준성능, 최대부하, 안정성, 가용성 등 여러 테스트를 관리할 수 있습니다.

---

### STEP 2. 테스트 생성

프로젝트 내부에서 수행할 성능테스트를 생성합니다.

테스트 생성 시 다음 정보를 정의합니다.

* 테스트명
* 테스트 목적
* 테스트 유형
* 테스트 설명
* 실행 일정

예:

* 기준 성능 테스트
* 최대 부하 테스트
* 안정성 테스트
* 가용성 테스트

테스트 목적을 명확하게 작성해 두면 테스트 종료 이후 결과 분석 및 리포트 작성에 도움이 됩니다.

---

### STEP 3. 시나리오 등록

성능테스트에서 실제 사용자의 업무 흐름을 재현할 시나리오를 등록합니다.

시나리오는 일반적으로 다음과 같은 사용자 업무 단위로 구성됩니다.

예:

로그인 → 고객조회 → 계약조회 → 상세조회 → 로그아웃

또는

* 로그인
* 고객 검색
* 계약 조회
* 해약환급금 조회
* 보험료 계산

각 시나리오는 실제 서비스 사용 패턴을 최대한 유사하게 반영하도록 구성하는 것이 중요합니다.

---

### STEP 4. 부하 설정

등록된 시나리오별로 부하 조건을 설정합니다.

대표적인 설정 항목은 다음과 같습니다.

* Virtual User 수
* 목표 TPS
* Ramp-Up 시간
* Ramp-Down 시간
* 테스트 지속시간
* Think Time
* 시나리오별 부하 비율

예:

* Virtual User: 300
* 목표 TPS: 104 TPS
* Think Time: 30초
* 테스트 지속시간: 60분

실제 운영 사용량 또는 목표 성능을 기준으로 부하 모델을 설정하는 것이 중요합니다.

---

### STEP 5. 테스트 실행

테스트 설정이 완료되면 테스트를 실행합니다.

테스트 실행 전 다음 항목을 확인합니다.

* 대상 시스템 접근 가능 여부
* 부하발생기 상태
* 테스트 데이터 준비 여부
* 시나리오 정상 동작 여부
* 모니터링 대상 서버 연결 여부
* 테스트 시간대 및 관계자 공유 여부

테스트 실행 이후 Performance Station에서는 설정된 부하 조건에 따라 Virtual User 또는 트래픽을 발생시킵니다.

---

### STEP 6. 실시간 모니터링

테스트 실행 중에는 주요 성능지표를 실시간으로 확인합니다.

대표적으로 다음 항목을 확인합니다.

* TPS
* 응답시간
* 오류율
* Virtual User
* CPU 사용률
* Memory 사용률
* WAS 상태
* DB 상태
* 외부 연계 시스템 상태

특정 시점부터 응답시간이 증가하거나 TPS가 감소하는 경우 서버 자원뿐만 아니라 DB, 외부 연계 시스템, 네트워크 등 전체 시스템 구간을 함께 확인해야 합니다.

---

### STEP 7. 결과 확인 및 분석

테스트가 완료되면 Performance Station에서 테스트 결과를 확인합니다.

주요 확인 항목은 다음과 같습니다.

* 평균 응답시간
* 최대 응답시간
* TPS
* 처리 건수
* 오류율
* Virtual User
* CPU / Memory 사용률
* 테스트 구간별 성능 변화

테스트 결과는 테스트 목적과 목표 성능을 기준으로 판단합니다.

예:

목표

* 목표 TPS: 104 TPS 이상
* 평균 응답시간: 1초 이하
* CPU 사용률: 80% 이하

결과

* 처리량: 110 TPS
* 평균 응답시간: 0.8초
* CPU 사용률: 65%

→ 목표 성능 충족

테스트 결과는 이후 결과 리포트 또는 성능검증 보고서 작성 시 활용할 수 있습니다.

---

## 처음 사용하는 사용자를 위한 권장 순서

Performance Station을 처음 사용하는 경우 다음 순서로 기능을 익히는 것을 권장합니다.

① 프로젝트 목록 확인
→ ② 기존 테스트 조회
→ ③ 시나리오 확인
→ ④ 부하 설정 확인
→ ⑤ 기존 테스트 결과 확인
→ ⑥ 신규 테스트 생성
→ ⑦ 테스트 실행

처음부터 테스트를 생성하기보다는 기존에 수행된 프로젝트와 테스트 결과를 먼저 확인하면 Performance Station의 구조를 쉽게 이해할 수 있습니다.

---

## 주의사항

### 권한에 따른 기능 제한

사용자 권한에 따라 다음 기능이 제한될 수 있습니다.

* 프로젝트 생성
* 프로젝트 수정 또는 삭제
* 테스트 생성
* 시나리오 등록 또는 수정
* 테스트 실행
* 사용자 및 권한 관리

메뉴가 보이지 않거나 버튼이 비활성화되어 있다면 사용자 권한을 먼저 확인합니다.

---

### 프로젝트가 조회되지 않는 경우

프로젝트 목록에 원하는 프로젝트가 보이지 않는 경우 대부분 다음 원인 중 하나입니다.

* 프로젝트 접근 권한 미부여
* 사용자 미등록
* 다른 조직 또는 프로젝트로 등록
* 프로젝트가 종료 또는 비활성 상태
* 검색 또는 필터 조건 적용

먼저 검색 조건과 필터를 초기화한 후 다시 확인하고, 계속 조회되지 않는 경우 관리자에게 프로젝트 권한을 요청합니다.

---

### 테스트 실행 전 설정 확인

잘못된 부하 조건으로 테스트를 실행하면 대상 시스템에 예상보다 큰 부하가 발생할 수 있습니다.

테스트 실행 전 반드시 다음 항목을 확인합니다.

* Virtual User
* TPS
* Ramp-Up
* 테스트 지속시간
* 대상 서버
* 테스트 대상 URL
* 테스트 시나리오

---

### 브라우저 종료와 테스트 실행

테스트 실행 방식에 따라 사용자의 브라우저를 종료하더라도 서버에서 테스트가 계속 실행될 수 있습니다.

따라서 테스트를 중단하려면 브라우저를 종료하기보다 Performance Station의 테스트 중지 기능을 이용합니다.

---

### 테스트 데이터 중복

동일한 사용자 ID 또는 동일한 테스트 데이터를 여러 Virtual User가 동시에 사용하는 경우 로그인 실패, 세션 충돌 또는 업무 오류가 발생할 수 있습니다.

성능테스트 전에 필요한 테스트 계정과 데이터를 충분히 확보하는 것이 좋습니다.
